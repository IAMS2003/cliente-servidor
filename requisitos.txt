Se requiere crear un chat para intercambiar mensajes en la comunidad académica de la Universidad usando java 21 con JDBC y JavaFX. El chat debe implementar las siguientes funcionalidades:

    Servidor:

        - Registra los clientes del chat. Se requiere un nombre de usuario, un email, una contraseña de acceso, foto y la dirección IP. 

        - Se debe restringir el número de usuarios conectados a la red, utilizando archivos de configuración.

        - Se debe registrar los logs de los mensajes enviados entre los usuarios y en los canales, adicionalmente incluir archivos compartidos de audio.

        - Se debe crear una transcripción de los mensajes de audio enviados entre clientes.

        - La información se almacenará en una base de datos relacional (Mysql), deben utilizar archivos de configuración para configurar la conexión.

        - Enviar mensajes a todos los usuarios y canales.

        - Cerrar conexiones.

        - Informes de usuarios: 

            - usuarios registrados

            - canales con usuarios vinculados

            - usuarios conectados

            - texto de los mensajes de audio enviados

            - logs

    Cliente:

        - Todos los usuarios son visibles a la comunidad.

        - Puede crear canales privados de comunicación y vincular usuarios según lo considere conveniente.

        - Cada usuario podrá aceptar o rechazar las solicitudes de pertenecer a un grupo en particular.

        - Se podrá intercambiar mensajes (texto o audio) con un usuario específico o con los miembros de un canal.

        - La información se almacenará en una base de datos relacional (H2Database), deben utilizar archivos de configuración para configurar conexión.

        - La aplicación cliente y servidor serán aplicaciones de escritorio. Se requiere crear aplicaciones con capas y con componentes.

El protocolo de comunicación entre el cliente/servidor será TCP-IP.

Aplicar patrones de diseño:

    - Fábricas

    - Observer

    - Object Pool

Aplicar principios SOLID

============================
Protocolo de comunicación propietario sobre TCP-IP
============================

El sistema usará un protocolo propio, orientado a mensajes, sobre TCP-IP. Cada mensaje intercambiado entre cliente y servidor tendrá la siguiente estructura binaria:

Cabecera (Header):
- Versión del protocolo (1 byte)
- Tipo de mensaje (1 byte)
- Longitud del cuerpo (4 bytes, entero sin signo, big-endian)
- ID de usuario (opcional, 4 bytes)

Cuerpo (Body):
- Datos codificados en UTF-8, JSON o binario según el tipo de mensaje

Tipos de mensaje (Type):
- 0x01: Registro de usuario
- 0x02: Autenticación
- 0x03: Mensaje de texto
- 0x04: Mensaje de audio
- 0x05: Solicitud de canal
- 0x06: Respuesta de canal
- 0x07: Mensaje a canal
- 0x08: Solicitud de lista de usuarios/canales
- 0x09: Envío de archivo
- 0x0A: Solicitud de cierre de sesión/conexión
- 0x0B: Notificación/Control

Ejemplo de mensaje:
[0x01][0x03][0x00 0x00 0x00 0x15][0x00 0x00 0x00 0x05][{"to": "canal1", "msg": "Hola a todos"}]

Reglas generales:
- Todos los mensajes deben respetar la estructura definida.
- El servidor valida la longitud y tipo antes de procesar.
- Los mensajes de audio y archivos se envían en formato binario, precedidos por metadatos en JSON.
- Los errores se comunican con mensajes de tipo 0x0B y un campo "error" en el cuerpo.
- El cierre de conexión se realiza con tipo 0x0A.

La especificación detallada estará en docs/arquitectura.md.
